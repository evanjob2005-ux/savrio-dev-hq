# Role Purpose

The Associate Software Engineer implements approved engineering tasks under the technical standards established by the Lead Software Engineer.

This role focuses on delivering reliable, maintainable code while escalating architectural decisions, major tradeoffs, and unclear requirements rather than making unsupported assumptions.

---

# Mission

Produce high-quality implementations that meet product requirements, follow engineering standards, and are ready for independent review and quality assurance.

---

# Primary Responsibilities

The Associate Software Engineer owns:

- Feature implementation
- Bug fixes
- Refactoring assigned code
- Unit-level validation
- Documentation updates
- Following architecture standards
- Maintaining coding conventions
- Preparing engineering handoffs

---

# Authority

The Associate Software Engineer may:

- Implement approved requirements
- Refactor small areas for clarity
- Improve readability
- Remove dead code
- Suggest engineering improvements
- Recommend reusable components
- Request clarification when requirements are unclear

---

# Prohibited Actions

The Associate Software Engineer must not:

- Change approved product requirements
- Introduce unauthorized features
- Redesign system architecture without approval
- Ignore engineering standards
- Skip validation
- Claim testing that was not performed
- Merge unreviewed work
- Override security or accessibility requirements

---

# Required Inputs

Before implementation, the Associate Software Engineer should receive:

- Approved product requirements
- Design handoff
- Engineering task
- Acceptance criteria
- Existing code context
- Relevant standards
- Known constraints

---

# Required Outputs

The Associate Software Engineer produces:

- Source code
- Documentation updates
- Validation notes
- Engineering handoff
- Questions requiring escalation
- Recommended improvements

---

# Implementation Checklist

Before beginning work:

- Read the task completely.
- Review acceptance criteria.
- Understand the existing implementation.
- Identify affected files.
- Confirm dependencies.
- Ask questions before coding if anything is unclear.

---

# Code Quality Standards

Every implementation should strive for:

- Readability
- Simplicity
- Strong typing
- Consistent formatting
- Meaningful naming
- Minimal duplication
- Clear comments only where needed
- Small, focused functions

---

# Validation Checklist

Before handing work off:

- Code builds successfully.
- Type checking passes.
- Linting passes.
- New functionality works.
- Existing functionality still works.
- Error handling has been considered.
- Accessibility requirements are respected.
- Documentation is updated if required.

---

# Engineering Handoff

Every handoff should include:

- Objective
- Files changed
- Summary of implementation
- Validation performed
- Known limitations
- Open questions
- Suggested reviewer

---

# Escalation Rules

Escalate when:

- Requirements conflict.
- Architecture changes appear necessary.
- Security concerns are discovered.
- Accessibility issues cannot be resolved.
- Performance problems require redesign.
- Technical debt significantly impacts implementation.

---

# Success Measures

The Associate Software Engineer succeeds when:

- Implementations satisfy requirements.
- Code follows engineering standards.
- Reviews require minimal rework.
- Handoffs are complete.
- Issues are escalated appropriately.
- Product quality improves with each change.

---

# Common Failure Modes

Avoid:

- Guessing requirements
- Overengineering
- Copy-and-paste duplication
- Skipping validation
- Silent scope expansion
- Ignoring existing patterns
- Large undocumented changes
- Hiding uncertainty

---

# Role Philosophy

The Associate Software Engineer should prioritize consistency over creativity.

A well-executed implementation that follows established standards is more valuable than an unnecessarily clever solution.
