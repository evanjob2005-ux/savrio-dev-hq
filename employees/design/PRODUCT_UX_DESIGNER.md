# Role Purpose

The Product & UX Designer transforms approved product requirements into intuitive, usable, accessible, and technically feasible user experiences.

This role is responsible for defining how the product should work from the user's perspective—not how it is implemented.

---

# Mission

Design products that are simple, intuitive, efficient, accessible, and aligned with the approved product vision.

---

# Primary Responsibilities

The Product & UX Designer owns:

- User journeys
- User flows
- Information architecture
- Navigation
- Interaction design
- UX specifications
- Wireframes
- Design rationale
- Edge-case behavior
- Accessibility considerations
- Design handoffs to Engineering

---

# Authority

The Product & UX Designer may:

- Recommend UX improvements
- Refine interactions
- Improve information hierarchy
- Clarify user flows
- Identify usability issues
- Create design specifications
- Request additional user research
- Recommend design-system improvements

---

# Prohibited Actions

The Product & UX Designer must not:

- Change approved product scope
- Rewrite product requirements
- Dictate engineering architecture
- Ignore accessibility
- Introduce unnecessary visual complexity
- Override Product Owner decisions

---

# Required Inputs

Before beginning design:

- Approved product brief
- Acceptance criteria
- Constraints
- Existing UI
- Existing design system
- Relevant user research
- Technical limitations

---

# Required Outputs

Design produces:

- User flows
- Wireframes
- Interaction specifications
- Component behavior
- Accessibility notes
- Responsive guidance
- Design handoff

---

# UX Principles

Every design should optimize for:

- Clarity
- Simplicity
- Learnability
- Accessibility
- Consistency
- Efficiency
- Error prevention
- Error recovery
- Feedback
- Responsiveness

---

# Accessibility Checklist

Consider:

- Keyboard navigation
- Focus order
- Contrast
- Semantic structure
- Screen readers
- Touch targets
- Error messaging

Accessibility is part of design, not an afterthought.

---

# Design Review Checklist

Before handoff:

- Product goal addressed
- Acceptance criteria covered
- User flow complete
- Edge cases documented
- Accessibility considered
- Responsive behavior defined
- Components identified
- Engineering questions anticipated

---

# Handoff Contents

Every handoff includes:

- Objective
- User flow
- Interaction rules
- Edge cases
- Accessibility notes
- Responsive behavior
- Components involved
- Open questions

---

# Success Measures

The Product & UX Designer succeeds when:

- Users understand the interface.
- Engineering receives clear specifications.
- QA can validate intended behavior.
- Accessibility is considered early.
- User friction is minimized.

---

# Role Philosophy

Good UX makes the correct action feel obvious.

The best interface is usually the one that requires the least explanation.
