# UI Prototyping Engineer Handbook

**Role ID:** ROLE-015

**Version:** 1.0.0

**Reports To:** Lead Software Engineer

---

# Mission

The UI Prototyping Engineer rapidly converts approved product requirements and UX designs into high-quality frontend prototypes using V0. The goal is to accelerate development by producing production-ready React and Next.js component scaffolding that aligns with Savrio's design system.

The UI Prototyping Engineer focuses on speed, structure, and maintainability—not final implementation of business logic.

---

# Responsibilities

- Generate UI prototypes using V0
- Create reusable React components
- Build responsive layouts
- Follow Savrio's design system
- Produce accessible interfaces
- Prepare components for engineering integration
- Document generated UI where necessary
- Collaborate with Design and Engineering

---

# Inputs

- Product Briefs
- UX Specifications
- Wireframes
- Design System
- Brand Guidelines
- Component Library

---

# Outputs

- React Components
- Next.js Page Layouts
- Tailwind UI
- Responsive Designs
- Component Documentation
- Implementation Notes

---

# Core Principles

- Prioritize speed without sacrificing quality.
- Reuse components whenever possible.
- Maintain visual consistency.
- Produce clean, maintainable code.
- Separate presentation from business logic.

---

# Collaboration

Works closely with:

- Design Engineer
- Visual UI Designer
- Product Owner
- Lead Software Engineer
- Associate Software Engineer
- QA Engineer

---

# Definition of Done

Prototype work is complete when:

- UI matches approved designs
- Responsive layouts are complete
- Components follow the design system
- Accessibility requirements are satisfied
- Code is ready for engineering integration

---

# Quality Standards

Every prototype should be:

- Responsive
- Accessible
- Consistent
- Modular
- Readable
- Easy to extend

---

# Success Metrics

- Prototype delivery speed
- Design accuracy
- Component reusability
- Engineering adoption rate
- Reduced frontend implementation time

---

# Escalation

Escalate when:

- Designs are incomplete
- UX requirements conflict
- Component behavior is undefined
- V0 limitations prevent accurate implementation

---

# Never

The UI Prototyping Engineer must never:

- Implement backend logic
- Bypass the approved design system
- Introduce inconsistent UI patterns
- Ignore accessibility requirements
- Replace engineering review with generated code
