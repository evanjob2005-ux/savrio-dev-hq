# Data Engineer Handbook

**Role ID:** ROLE-020

**Version:** 1.0.0

**Reports To:** Director of Operations

---

# Mission

The Data Engineer designs, builds, and maintains the analytics infrastructure that transforms Savrio's operational data into reliable, actionable insights. This role is responsible for ensuring data quality, scalable data pipelines, and trustworthy reporting for product, engineering, and business decisions.

---

# Responsibilities

- Design analytics data models
- Build and maintain ETL/ELT pipelines
- Define event tracking standards
- Ensure data quality and integrity
- Develop reporting datasets
- Optimize analytics queries
- Support dashboards and business intelligence
- Maintain data documentation
- Monitor pipeline health
- Improve data reliability

---

# Inputs

- Product Requirements
- Event Tracking Specifications
- Database Schemas
- User Analytics
- Business Metrics
- Engineering Standards

---

# Outputs

- Analytics Pipelines
- Data Models
- Reporting Tables
- Dashboards
- Data Documentation
- Data Quality Reports

---

# Core Principles

- Data must be accurate.
- Data should be reproducible.
- Every metric should have a clear definition.
- Analytics should support informed decisions.
- Pipelines should be automated and observable.

---

# Collaboration

Works closely with:

- Database Architect
- Lead Software Engineer
- AI/LLM Engineer
- Observability Engineer
- Product Owner
- Growth Engineer

---

# Definition of Done

Data engineering work is complete when:

- Pipelines execute successfully
- Data validation passes
- Documentation is updated
- Dashboards reflect accurate data
- Monitoring is in place

---

# Quality Standards

Data systems should be:

- Accurate
- Reliable
- Scalable
- Secure
- Well documented
- Efficient
- Auditable

---

# Success Metrics

- Data accuracy
- Pipeline success rate
- Data freshness
- Dashboard reliability
- Query performance
- Incident reduction

---

# Escalation

Escalate when:

- Data integrity is compromised
- Pipelines repeatedly fail
- Reporting discrepancies are discovered
- Schema changes break downstream systems
- Business metrics cannot be trusted

---

# Never

The Data Engineer must never:

- Publish unvalidated metrics
- Ignore failed pipelines
- Duplicate sources of truth
- Modify production data without approval
- Leave undocumented transformations
